A bigger one. Connections now hold many databases, Valkey joins the engine list, and Tusk's MCP server works from any AI client — with several windows at once.

## Connections hold many databases

- **One profile per server.** The database field is optional on the Postgres family, MySQL/MariaDB, MSSQL and ClickHouse; a blank one connects you to the engine's default, and you pick the real one from the title bar. Test Connection now answers "OK — PostgreSQL 16 · 4 databases".
- **One profile per Cloudflare account.** D1 profiles list every database of the account in the title bar; pick one instead of keeping a profile per database. Older uuid-based profiles still work.
- **The database dropdown grew up.** Over ten databases it becomes a searchable palette (⌘K → "Open a database…") plus your ten most recent; under ten it stays a flat list.
- **Sizes in the sidebar and dropdowns.** Tables show their storage size where the engine reports it (Postgres, MySQL, ClickHouse, MSSQL); databases show theirs in the dropdown; Redis and Valkey show the number of keys per db index.

## New engine

- **Valkey**, first-class: its own form entry, its own version line (`Valkey 8.x`), same keys-and-indexes interface as Redis.

## MCP for any client, any number of windows

- **`tusk mcp`** turns the running app into an MCP server for Claude Desktop, Claude Code, Cursor, opencode — anything that speaks MCP. It finds the running Tusk by itself, follows restarts, and answers "start Tusk first" when none is running.
- **`run_sql`** returns rows to the agent, gated by Settings ▸ AI ▸ **Agents Can Run Queries** (Never / Read-only / All). Read-only runs single SELECT-type statements, inside a server-enforced `READ ONLY` transaction on Postgres and MySQL — writes hidden behind a function are refused by the server, not by a keyword scan. Every agent run lands in the console and History.
- **Several Tusk windows at once.** `list_connections` shows every running window; every tool takes a `connection` argument to pick one. Without it, the most recently active window answers.
- The D1 connection test is fixed: Cloudflare blocks `sqlite_version()` server-side, so the test now verifies auth, account and database through its own probe and reports the service version.

## Interface

- **The grid toolbar moved up.** View switcher (Data / Structure / Index), + Row, the row count, filters and paging now sit above the table, below the tabs.

## Under the hood

- Dev builds sign correctly again (identities are matched by hash — non-ASCII names in certificate names were silently skipping signing), so the macOS Keychain stops re-prompting after every rebuild.

## Install

**macOS** (14 Sonoma or later, Apple Silicon): Tusk updates itself. Or download `Tusk-0.3.0-arm64.dmg`, or run `brew upgrade tusk`.

**Windows** (x64 or ARM64): download the zip for your machine, unzip it, and run `Tusk.exe`. SmartScreen may warn the first time because the build isn't code-signed yet: click **More info ▸ Run anyway**.

**Linux** (x86_64): `.deb` for Ubuntu, `.rpm` for Fedora, `.pkg.tar.zst` for Arch, all below.
